# 被害者ホップ再検証サマリー（元の条件＋effects）

作成: 2026-10-31 / 解析: モコ (Muse) / モデル: Muse Spark 1.3
対象: リスト外の送り元から GDGVILYX4RAT…（pi chain mall）／GBU7PR3VSIW…（teltlk）への入金について、アキラの元の抽出条件を effects 込みで再実行した。
実行結果: HTTP 429 なし。全ステップで上限到達なし（ターゲット履歴 PCM 178,965件・TEL 111,675件を全件取得）。

## type_i: 51 の解釈（Step 0 で検証）

- type_i=51 は `claimable_balance_claimant_created`。predicate は `{"not": {"rel_before": 秒}}` で、これは Stellar の請求述語で「effect作成時刻＋rel_before 秒より前には請求できない」＝ **解除時刻 = effect の created_at + rel_before 秒** と読むのが正しい。
- 根拠: type_i=52（`claimable_balance_claimed`、同一 balance_id）の請求は、検証した全件で算出した解除時刻以降に発生していた（例: rel_before=92,835,410秒のトランシェは解除 2025-08-25T06:42:58Z → 請求 2025-08-25T08:25:48Z。14日ロックのトランシェも解除後に請求）。
- アカウントは複数の type-51 トランシェを持ち、rel_before は 1,209,600秒（14日）から約9,100万秒（約2.9年）まで様々。
- 条件(c)の主たる読み: 送金時点で「直近に請求済みのトランシェ」の解除時刻からの経過時間（請求していない資金は送れないため）。副次的な読み（全トランシェの最新解除時刻からの経過）でも結果のバンドは両ターゲットとも完全に一致した。

## 残高再構成（条件(b)）の方法

- effects を台帳順に積算: type 0（starting_balance）＋ type 2（credited）－ type 3（debited）、native のみ。type 52（請求）は type 2 に既に含まれるため二重計上しない。
- 取引手数料は transactions エンドポイントから差し引く（fee_charged ストループス÷10⁷、fee_account が本人の取引のみ、送金取引まで累計）。
- 検証: 再構成した最終残高は現在残高と完全一致（1件）／差 0.03〜0.05 Pi（2件）。再構成と現在残高の差が 0.1 Pi を超える送り元は「残高不明」として推測しない。本検証では条件(c)通過者の残高は全員確定できた（不明 0件）。

## 解釈と注意点

- 厳密な元の3条件（受け取りなし＋解除後3分未満＋残高2 Pi未満）に当てはまる送り元は実在し、形状は教科書的なドレイン（解除→即請求→ほぼ全額送金→残高約1 Pi）だが、**両ハブ合わせても初回送金ベースで5件・後続送金込みで6件と少なく、金額も小さい**。リスト外入金の大半は (a) で落ちる通常型（受け取り履歴あり）で、(a)通過者の大半も解除から60分以上経ってからの送金だった。
- 本検証は全期間・全送り元が対象。アキラの元の抽出は2023年の特定期間と「1,000 Pi以上の送金をしたスパム候補」という別の入口条件を使っており、条件の入口と期間が異なるため、本結果は元のリスト作成を直接否定も肯定もしない。特に PCM のフルマッチが 2025 年以降に寄っている点は、元の2023年抽出とは位相が違う。
- フルマッチ例の送金後残高が約1 Pi に集まるのは、Pi の最低残高（ベースリザーブ）相当とみられる。
- ロック解除時刻は payments からは取れないが effects からは取れる、というアキラの補足は本検証で裏付けられた。
- チェーン上の資金移動は同一グループ・関与の可能性を示すもので、人物の特定や盗みの断定にはならない。
